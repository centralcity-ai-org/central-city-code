# A2A mapping spike — 25 September 2026

This repository now contains a **pure mapping and validation boundary**, not a deployed A2A server or a complete A2A implementation. It performs no network calls, authentication, database writes, model execution or spending. Nothing imports it into the application's routes.

## Executable boundary

`parseA2AIntent(raw, selection)` accepts a bounded JSON string and explicit version/binding. Its return value is **untrusted intent**. It does not turn a message ID into authenticated identity or a guaranteed idempotency key.

| Operation        | Implemented local representation                                                                                                                     | Remaining service behavior                                                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `SendMessage`    | One new `ROLE_USER` message with one nonempty text part; explicit `returnImmediately: true`; optional zero history length and JSON output preference | Authenticate caller; choose provider from a granted route; reserve authority; durably deduplicate; queue execution; bind opaque wire IDs |
| `GetTask`        | Task-ID lookup intent; omitted or zero history length                                                                                                | Authorize every lookup against caller, tenant and resource; fetch authoritative state                                                    |
| `CancelTask`     | Cancellation intent only; response helper refuses to acknowledge a task that is not already canceled                                                 | Authorize; atomically stop new work; reconcile remote cancellation; preserve uncertainty when acknowledgement is absent                  |
| Task projection  | Native execution state and completed JSON output artifact, with explicitly supplied opaque IDs                                                       | Persist scoped ID mappings; use fresh authorized native data                                                                             |
| Success response | Send uses `result.task`; get/cancel use `result` containing the task                                                                                 | HTTP status, content type, errors and caller-specific response authorization                                                             |

The queue cannot yet provide blocking SendMessage. The subset therefore requires `returnImmediately: true` instead of silently weakening the omitted/false behavior. This distinction follows `SendMessageConfiguration` in the [normative protobuf](https://github.com/a2aproject/A2A/blob/173695755607e884aa9acf8ce4feed90e32727a1/specification/a2a.proto).

Requests are limited to 64 KiB UTF-8; text to 12,000 characters; completed output to 32 KiB UTF-8. Identifiers use a bounded ASCII subset. JSON-RPC notifications and batches are rejected. Local errors have typed codes and generic descriptions; they are **not** a full A2A wire error serializer.

This subset rejects unknown fields as well as known unsupported features. That is intentionally stricter than the specification's forward-compatibility recommendation to ignore unknown fields; it protects an unintegrated intent boundary from silently dropping meaningful requests. This difference prevents a claim of general schema acceptance. [Specification, section 5.7](https://a2a-protocol.org/v1.0.0/specification/).

## Execution and review

| Native status | Projected A2A status   |
| ------------- | ---------------------- |
| `queued`      | `TASK_STATE_SUBMITTED` |
| `running`     | `TASK_STATE_WORKING`   |
| `completed`   | `TASK_STATE_COMPLETED` |
| `failed`      | `TASK_STATE_FAILED`    |
| `canceled`    | `TASK_STATE_CANCELED`  |

Projection copies completed JSON output into a data artifact. It excludes native requester/provider IDs, job IDs, input, internal errors, cost and owner acceptance. The caller supplies separately scoped wire task/context IDs; the module does not prove ownership of those IDs. Completed/failed/canceled status uses `completedAt`, so accepting a result later does not rewrite execution history. Output is copied rather than returned by mutable reference.

An A2A completion is not Central City owner acceptance, independent validation, settlement or a quality guarantee. A parsed cancel request changes no state. Cancellation is not a reversal of previous effects, and terminal tasks must not be reopened by follow-up input. These lifecycle distinctions are consistent with [Life of a Task](https://a2a-protocol.org/v1.0.0/topics/life-of-a-task/). The present parser rejects continuation/context fields entirely.

## Unsupported and untested

No Agent Card is advertised. No auth scheme, OAuth audience validation, endpoint ownership challenge, credential translation, tenant routing, network egress, SSRF defense, signed card, or public discovery endpoint is supplied here. Existing native authentication is not relabeled as A2A authentication. Never pass native bearer tokens to a third-party A2A service.

Streaming, subscriptions, push notifications, list operations, extended cards, multi-turn tasks, files/URLs/raw parts, arbitrary structured inputs, extensions, service-parameter extraction from HTTP, blocking send, remote task ingestion, retries, remote cancellation, and A2A error envelopes are unsupported. The native model cannot represent interrupted/auth-required/rejected states distinctly; do not coerce such remote states into existing statuses. MCP, gRPC, HTTP+JSON and legacy A2A remain separate work.

The official protocol's security model requires authentication and object-level authorization; wire parsing alone establishes neither. [Official specification, sections 7 and 13](https://a2a-protocol.org/v1.0.0/specification/).

## Evidence and next integration

Run `pnpm exec tsx --test tests/a2a-mapping.test.ts` from the application directory. Eleven tests cover literal request/task fixtures, version/binding rejection, injected authority fields, unsupported content, size bounds, private-field exclusion, immutable output copies, separate acceptance, all native execution statuses, and cancellation acknowledgement guards. These are local unit tests, not independent interoperability evidence.

Next implement a private authenticated A2A façade for one approved deterministic provider. Reuse native application services rather than loopback HTTP. Before opening any route, add principal-scoped wire ID storage and durable message deduplication with body hashes; ensure tenant and directional grant checks cannot be supplied by message metadata. Then test an independent pinned A2A client across the real HTTP boundary, including wrong-principal task lookup/cancel, duplicate message conflicts, revoked grants, blocking-mode rejection, truthful error mapping and cancellation races. Select the actual authentication scheme before emitting an Agent Card. Keep the interface private until those cases pass.
